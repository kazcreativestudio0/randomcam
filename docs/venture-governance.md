# RandomCam 非公表事業・内部統治方針

## 目的

RandomCam は KAZ Creative Studio Hub（以下、Hub）に属する独立プロジェクトとして、Hub 内で予算・権限・リスク・進捗を管理する。一方、現段階では Hub が RandomCam を運営している事実を、宣伝目的で外部に公表しない。

これは利用者や取引先に必要な情報を隠すためではない。製品の検証段階では、RandomCam 単独ブランドとして体験・安全運用・継続性を確かめ、Hub との関係を不用意に拡散しないための方針である。法律、決済事業者、利用者保護のために必要な表示・説明は常に正確に行う。

## 情報の区分

| 区分 | 内容 | 扱い |
| --- | --- | --- |
| 外部公開 | RandomCam の機能、利用条件、禁止事項、通報方法、プライバシー、問い合わせ先、障害情報 | RandomCam 名義で正確に公開する |
| Hub 内部 | Hub との関係、予算、運営者、管理アカウント、収益計画、未公開のKPI、事故記録 | Hub の関係者だけが閲覧する |
| 法的・契約上の開示 | 運営主体、連絡先、責任者情報、請求・税務情報など、適用法や契約で必要な事項 | 必要な範囲で正確に開示する。非公表方針を理由に虚偽表示しない |
| 秘密情報 | パスワード、APIキー、Cloudflare・GitHubの認証情報、通報証拠、個人情報 | ソースコード・SNS・公開資料に置かず、最小権限で管理する |

## ブランド運用

- 外部サイト、SNS、検索結果、紹介文、サポート返信は原則として **RandomCam** 単独名義を使う。
- Hub のロゴ、代表者の個人SNS、他事業のブランドを、RandomCam の宣伝素材へ自動的に載せない。
- 「KAZ Creative Studio Hub が運営している」「Hub の公式事業である」といった表現は、外部公表を決めるまでは使わない。
- ただし、利用規約・プライバシー表示・特定商取引法等で運営主体や連絡先の表示が求められる場合は、適用範囲を確認して正確に表示する。
- RandomCam 名義であっても、実際の運営能力や安全対策を超える表現はしない。

## アカウント・ドメイン・権限管理

- Cloudflare、GitHub、将来のドメイン、SNS、分析ツール、決済事業者は、Hub 内の資産台帳に「用途・所有者・復旧方法・二要素認証の有無」を記録する。
- 初期は運営者（一馬）が管理者とし、管理権限は必要最小限にする。共同作業者を追加する場合は、個人共有のパスワードではなく個別アカウントで付与する。
- 管理画面、Cloudflareの秘密情報、バックアップ用コードはパスワードマネージャー等の非公開保管場所に保存し、チャット・ソースコード・公開ドキュメントへ記載しない。
- ドメインを取得するまでは Cloudflare の公開URLを使う。取得後もドメイン登録者、更新日、支払い方法、失効時の復旧手順をHub内で管理する。
- 退職・協力終了・端末紛失など権限に影響する事象があれば、当日中にアクセスを見直し、必要に応じて秘密情報を更新する。

## 問い合わせ・法的表示

- 利用者向けには、問い合わせ先、対応時間の目安、通報方法、プライバシー上の扱いを RandomCam のページで明記する。
- 年齢制限、禁止事項、通報後の画像保存期間、停止基準は曖昧にせず、実際の運用と一致させる。
- 法令、裁判所、捜査機関、決済事業者、プラットフォームから適法な照会があった場合は、独断で隠蔽せず、必要に応じて専門家へ相談して適法に対応する。
- 重大な安全事案や個人情報事故では、必要な通知・報告を優先し、非公表方針を理由に利用者保護を遅らせない。

## Hub 内のステータス管理

RandomCam はHub内で次の状態を持つ。外部へ出すかどうかと、製品を公開するかどうかは別に判断する。

| 状態 | 意味 | 外部での扱い |
| --- | --- | --- |
| 構想 | 事業仮説・安全設計を検討中 | 公表しない |
| 非公表ベータ | 製品を限定的に検証中 | RandomCam 単独ブランドで必要情報のみ公開 |
| 運用検証 | 指標・通報対応・費用を継続検証中 | Hub との関連は公表しない |
| 拡大判断 | 集客・法人化・有料化を検討中 | 必要に応じて法的表示を見直す |
| Hub公表 | Hub の事業として外部紹介する | 承認後に段階的に切り替える |
| 保留・停止 | 安全性、法務、費用、品質のいずれかで停止 | 公開停止と関係者対応を優先する |

Hub 内の月次メモには、現在の状態、責任者、公開中のURL、費用、利用規模、通報状況、次回判断日、未解決リスクを残す。

## 外部へ情報を出す判断条件

Hub との関係を外部に出す判断は、次を満たす時に行う。

1. RandomCam の安全運用、通報対応、プライバシー表示、問い合わせ対応が安定している。
2. Hub名義を出すことが、利用者の信頼や事業上の目的に具体的に役立つ。
3. 運営主体、法人化、税務、契約、問い合わせ窓口を正確に説明できる。
4. Hub の他事業へのリスクやブランド影響を確認している。
5. Hub の責任者が、公開範囲・公開日・説明文を承認している。

単なる話題作りや、運用準備が整わない段階での発表はしない。

## 事故・通報時のエスカレーション

1. **通常通報**: 自動停止・証拠保存・管理画面での判断を既定の手順で行う。
2. **重大通報**: 未成年の疑い、性的搾取、脅迫、個人情報の悪用、差し迫った危険がある場合は、公開時間の停止を含めて運営者へ即時連絡する。
3. **技術・個人情報事故**: 誤公開、認証情報漏えい、証拠画像への不正アクセスが疑われる場合は、該当機能を止め、アクセス権とログを保全し、必要に応じて専門家・関係事業者へ相談する。
4. **対外対応**: 事実確認前に推測で説明しない。必要な利用者保護と法的な通知を優先し、Hubとの関係を伏せることを目的に虚偽の説明はしない。

## 将来、Hub事業として公表する場合の切替手順

1. Hub 内で公表目的、対象者、公開範囲、責任者、公開日を承認する。
2. 利用規約、プライバシー表示、問い合わせ先、必要な法的表示を実態に合わせて更新する。
3. サイト、SNS、メディア資料、採用・協業資料に載せるHubとの関係を統一し、誤解を生む表現をなくす。
4. Cloudflare、ドメイン、SNS、決済、データ保管の所有・権限台帳を確認し、組織管理へ移行する。
5. 既存利用者への影響（連絡先、プライバシー、データ取扱い）が変わる場合は、事前にわかりやすく告知する。
6. 公表後30日間は問い合わせ、報道・SNS反応、なりすまし、セキュリティを重点的に監視する。

## 見直し

この方針は、公開前、外部連携前、有料化前、法人化前、重大事故後に必ず見直す。非公表であることより、利用者の安全、正確な表示、法令遵守、継続可能な運営を優先する。
