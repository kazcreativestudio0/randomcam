# RandomCam SEO・多言語設計

## 目的と前提

RandomCam は、成人が匿名で世界中の相手と 1 対 1 のビデオ・音声会話を始められるサービスである。用途は友達づくり、文化交流、言語練習に限定し、恋愛目的、性的な利用、露出、嫌がらせ、勧誘を禁止する。

SEO の目的は短期的な検索順位だけではない。検索利用者に誤解のない内容を伝え、信頼できる成人向けコミュニケーションサービスとして見つけてもらうことである。初期の主対象は海外で、表示言語は日本語と英語から始める。

## 初期ページ構造

| URL | 役割 | インデックス |
| --- | --- | --- |
| `/` | 通話開始画面。短い価値説明、成人自己申告、ルール、開始導線 | 可 |
| `/en` | 英語の説明・開始導線。`/` を英語既定にする場合は不要 | 可 |
| `/ja` | 日本語の説明・開始導線 | 可 |
| `/how-it-works` | 匿名性、ランダムマッチ、カメラ・マイク、スキップの説明 | 可 |
| `/safety` | 成人限定、禁止事項、通報、停止方針、プライバシー保護 | 可 |
| `/community-guidelines` | 詳細なコミュニティガイドライン | 可 |
| `/privacy` | データ、通報証拠、保存期間、問い合わせ先 | 可 |
| `/terms` | 利用規約 | 可 |
| `/report` | 通報方法と緊急時の案内。個別通報画面自体は非公開 | 可 |
| `/admin/*` | 運営者専用画面 | **不可** |

通話中、待機中、マッチ後、通報フォーム、管理画面など、検索価値のない状態画面は `noindex` にする。URL を量産せず、各ページは固有で利用者に役立つ内容を持たせる。

## 言語・URL 方針

### 初期

- 既定はブラウザの `Accept-Language` を読む。
- `ja` または `ja-*` は日本語、それ以外は英語を初期表示する。
- 初回判定後は、ユーザーが選んだ言語を Cookie または localStorage に保存し、次回はその選択を優先する。
- 画面上部または設定メニューに、常に手動の言語切替を置く。自動判定のみで固定しない。
- 検索向けの説明ページは言語ごとに安定した URL を使う。推奨は `/en/...` と `/ja/...`。通話画面は選択言語を保持しつつ一つの実装を共有してよい。

### 将来

- 新しい言語は、利用者が理解できる安全ルール・通報導線・プライバシー文書を同時に翻訳できる場合だけ追加する。
- 方言は別言語として URL を増やす前に、同じ言語の文体差として翻訳カタログで管理する。独自の有用な説明がない地域別ページは作らない。
- 対応予定の優先候補は、実際の利用・待機列データを見て決める。英語、日本語の次を先に固定しない。

## 英日コンテンツ方針

- 逐語訳ではなく、目的・禁止事項・法的意味が同じになるローカライズを行う。
- サービス説明は誇張しない。例: 「安全」は絶対保証ではなく、「通報・停止・運営確認の仕組みを設けている」と具体的に書く。
- 英語の主要見出し例: `Random video chat for friends, culture, and language practice`。
- 日本語の主要見出し例: `世界の誰かと、今すぐ話すランダムビデオチャット`。
- 恋愛・性的な出会いを連想させる語、競合サービス名、過度に刺激的な表現をタイトルや説明文に使わない。
- 法的文書、禁止事項、通報後の証拠保存期間は、翻訳ごとに意味の差がないか運営が確認する。

## メタデータ

各インデックス対象ページに、言語固有の以下を設定する。

- `title`: ページ固有の内容 + `RandomCam`。おおむね 50〜60 文字を目安に、切り詰められても意味が通る文にする。
- `description`: ページ固有の要約。機能、対象、禁止事項を必要に応じて明示する。定型文の使い回しをしない。
- `canonical`: その言語版自身の正規 URL。
- `hreflang`: `en`、`ja`、将来追加する言語と `x-default` を相互参照する。
- `robots`: 公開説明ページは `index,follow`、通話状態・管理・個人情報を含む画面は `noindex,nofollow`。

トップ英語版の例:

```text
Title: RandomCam — Random Video Chat for Global Conversations
Description: Meet a new person for a respectful one-to-one video conversation. For adults, friendship, culture, and language practice.
```

トップ日本語版の例:

```text
Title: RandomCam — 世界とつながるランダムビデオチャット
Description: 成人限定。友達づくり、文化交流、語学練習のために、世界の誰かと1対1で話せるランダムビデオチャットです。
```

## OGP と共有表示

- ページごとに `og:title`、`og:description`、`og:url`、`og:locale` を設定する。
- 初期 OGP 画像は、顔写真や性的連想を避け、RandomCam のロゴ、地球・会話・安全なコミュニティの抽象表現を使う。
- 推奨サイズは 1200 x 630。言語別に文字を入れる場合は英日で別画像にする。
- `twitter:card` は `summary_large_image` を使用する。
- 実際の利用者、通報画像、通話画面のスクリーンショットを OGP に使わない。

## robots.txt と sitemap.xml

### robots.txt

- `Sitemap: https://{production-domain}/sitemap.xml` を記載する。
- `/admin/`、通話セッション URL、内部 API、通報証拠へのパスはクロールさせない。
- `Disallow` は秘匿の代替ではない。管理画面と証拠データは認証・アクセス制御で保護し、`noindex` も付ける。

### sitemap.xml

- 公開説明ページだけを掲載する。
- 言語版ページと `hreflang` を対応付ける。
- 更新日時は内容が実際に変わった時だけ更新する。
- 待機列、通話、検索パラメータ付き URL、管理 URL は含めない。

## 構造化データ

- トップページには `WebSite` と `Organization` を JSON-LD で追加する。
- 説明ページには内容に応じて `WebPage`、安全ガイドには `FAQPage` を追加できる。ただし FAQ はページ上に実際に表示する質問と回答だけにする。
- 架空のレビュー、星評価、利用者数、受賞歴、アプリ配信実績は構造化データに入れない。
- `Organization` の連絡先、ロゴ、公式 SNS は、実際に運用を開始したものだけ掲載する。

## 翻訳の運用

1. 原文のキーをコードから分離する（例: `locales/en.json`, `locales/ja.json`）。
2. 表示文だけでなく、タイトル、説明文、OGP 文言、エラーメッセージ、禁止事項も同じカタログで管理する。
3. 変更時は英日を同時に更新し、未翻訳キーを CI で検出する。
4. 安全・規約・プライバシーの変更は公開前に内容確認を行う。
5. 機械翻訳で下書きは可能だが、公開前に対象言語を自然に読める人が確認する。

## 表示言語の実装方針

- サーバー側で `Accept-Language` を読み、初期 HTML の `lang` 属性とメタデータを一致させる。クライアントで後から言語だけを差し替えると、検索・共有・アクセシビリティの整合性が下がる。
- 選択済み言語がある場合はそれを最優先する。
- 言語切替時には対応する言語 URL に移動し、`hreflang` / canonical が一貫するようにする。
- 画面の `lang` 属性は選択言語に合わせ、右から左へ書く言語を追加する時は `dir` も管理する。
- 地理情報や IP アドレスだけで言語・国を決めない。旅行者や VPN 利用者を誤判定しやすいためである。

## やってはいけない SEO

- 「Omegle」「OmeTV」など競合名をタイトル、本文、隠しテキストに埋め込んで集客しない。
- キーワードの詰め込み、不可視テキスト、言語ごとの重複ページ、低品質な地域名ページを作らない。
- 性的・出会い系と誤認させる見出しや画像でクリックを誘わない。
- 自動生成した記事、架空の利用者レビュー、購入リンク、相互リンク網で順位を操作しない。
- 公開前の薄いページを大量にインデックスさせない。
- 管理 URL、通報画像、個人識別子を検索結果やサイトマップに露出させない。

## 実装優先順

1. `/` の実態に合うタイトル・説明、`lang` 属性、年齢・禁止事項の明示を整える。
2. `/en` と `/ja` の公開説明ページ、言語切替、翻訳カタログを追加する。
3. `/how-it-works`、`/safety`、`/community-guidelines`、`/privacy`、`/terms` を英日で用意する。
4. canonical、`hreflang`、OGP、robots、sitemap、基本 JSON-LD を追加する。
5. Search Console / Bing Webmaster Tools に独自ドメインを接続した時点で登録し、インデックス・検索語・エラーを月次確認する。
6. 利用データと通報傾向を確認して、次の言語を追加する。

## 実装開始前に確認したいこと

- 運営会社名または運営者の表記名、連絡先メールアドレス、対象法域。プライバシー・規約・構造化データに必要になる。
- 成人年齢を「18歳以上」で統一してよいか。公開する全言語の安全文書に同じ基準を出す。
- 英語の既定地域表記を国際英語にするか、米国英語にするか。初期は国際英語を推奨する。
- サービス公開時に使用する正式ドメイン。現在の Cloudflare の仮 URL では canonical・OGP・Search Console の最終設定を固定しない。
