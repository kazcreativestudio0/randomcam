# 有料ホスト型 RandomCam の実現可能性チェック

更新日: 2026-07-30  
位置付け: KAZ Creative Studio Hub 内部の将来フェーズ用メモ。初期の無料・匿名 RandomCam とは別事業段階として扱う。外部公開を前提とした資料ではない。

## 対象にする構想

利用者がコインを購入し、本人確認済みの**成人ホスト**と、文化交流・言語会話などの非性的な一対一ライブ会話を行う。通話時間またはギフトに応じて、プラットフォームがホスト報酬を分配する。

以下は、恋愛目的、性的内容、ヌード、性的サービス、勧誘を禁止した場合だけを対象にする。これらを許容する設計は、決済・安全・法務の前提が根本から変わるため、この計画の範囲外である。

## 結論

**条件付きで可能。**

技術面では、Stripe Connect のようなマーケットプレイス向け決済を使えば、プラットフォーム集金、本人確認を伴うホスト登録、売上の分配、銀行口座への払出しは実装できる。Stripe は、複数当事者間の決済・払出しを扱うプラットフォーム／マーケットプレイス用途として Connect を案内している。  
ただし、開始可否は「非性的サービスを実際に維持できるか」「決済会社が個別審査で承認するか」「雇用・税務・個人情報の運用を固められるか」に依存する。**決済導入前に Stripe へ事業内容とモデレーション設計を提示し、書面またはサポート記録で可否確認することが必須。**

## 1. 決済・報酬分配は成立するか

### 仕組み

Stripe Connect は、プラットフォームが利用者から受けた決済を、接続アカウント（ここではホスト）へ配分・払出しする用途を提供している。ホストは Stripe が提供するオンボーディングで本人・受取口座の確認を行い、プラットフォームは決済方式に応じて手数料・払出し時期を管理できる。

```text
利用者 ── カード等でコイン購入 ──> RandomCam の Stripe 決済
                                           │
                           運営取り分・決済費・返金原資を管理
                                           │
                                  ホスト別の報酬を計算
                                           ↓
                          Connect 接続アカウント ──> ホストの銀行口座
```

根拠:

- [Stripe Connect の概要](https://docs.stripe.com/connect/how-connect-works) — 販売者・サービス提供者への支払い、本人確認、国際払出しを含む設計を説明。
- [Connect の払出し](https://docs.stripe.com/connect/payouts-connected-accounts) — 接続アカウント残高と払出し時期を説明。
- [接続アカウントの銀行口座管理](https://docs.stripe.com/connect/payouts-bank-accounts?locale=en-GB) — 受取口座情報は Stripe-hosted onboarding で収集することを推奨。

### 推奨する初期の資金フロー

1. 利用者はコインを購入するが、コインの規約・有効期限・返金基準を明記する。
2. 通話開始／通話時間の確定後に、ホスト報酬を台帳へ計上する。
3. 返金・異議申立てに備え、即時全額払出しをせず、短い保留期間と上限を設ける。
4. 確定した報酬だけを週次または隔週で払出す。
5. すべての決済、通話実績、報酬計算、返金、払出しを追跡可能な台帳に残す。

「利用者の預り金」を恣意的・長期に保有する設計は避ける。Stripe も、サービス完了確認のような明確な目的がある場合を除く任意の保留を勧めていない。

## 2. 返金・不審請求・損失の責任

決済方式によって、返金とチャージバックの引落先・対応者が変わる。たとえばプラットフォームで課金する方式では、返金・チャージバックがプラットフォーム残高から引かれる場合がある。Express／Custom 型では、接続アカウントの残高不足時にプラットフォームが最終的に負担する構成がある。

根拠:

- [Connect の残高と負債](https://docs.stripe.com/connect/account-balances) — 決済をどちらのアカウントで作成したか、損失責任の設定により負担者が変わることを説明。
- [Connect の不審請求対応](https://docs.stripe.com/connect/disputes?locale=en-GB) — 異議申立てを誰が回答し、どの残高から差し引かれるかを説明。
- [マーケットプレイスの返金・異議申立て](https://docs.stripe.com/connect/end-to-end-marketplace) — settlement merchant ではプラットフォームが異議申立て責任を持つと説明。

開始前に決めること:

- 「未使用コイン」「通信障害」「ホスト不在」「利用規約違反」の返金基準と期限
- チャージバック時の一次対応者、ホストへの求償条件、保留金の上限
- 不正利用検知、利用停止、証拠保全の手順
- 国・通貨ごとの払出し可否と手数料

## 3. ホストは雇用か業務委託か

契約名を「業務委託」にしても、それだけでは決まらない。厚生労働省は、労働者性を、他人の指揮監督下で労務を提供しているか、報酬がその労務の対価かという使用従属性を中心に、個別事情から総合判断するとしている。

根拠: [厚生労働省「労働者とは」](https://www.mhlw.go.jp/stf/seisakunitsuite/bunya/koyou_roudou/roudoukijun/keiyaku/index02.html)

### 業務委託として運用したい場合の実務上の線引き

- ホスト自身が稼働する日時・量を選べるようにする。
- 他サービスでの活動を不当に制限しない。
- 固定シフト、常時待機命令、詳細な会話台本・毎分の業務指揮を基本にしない。
- 報酬は成果・提供実績に連動させ、最低時間給・固定給を当然の前提にしない。
- ただし、未成年保護、非性的方針、迷惑行為禁止、本人確認、通報調査への協力などの品質・安全ルールは契約で定める。

これらは業務委託と断定する基準ではない。実態として、断れない業務指示、時間・場所の拘束、代替不能性、専属性、時間給的な報酬が強いほど雇用と評価される可能性が高まる。雇用にするなら、賃金、労働時間、労働保険・社会保険等を別途設計する必要がある。

## 4. 日本の税務・源泉徴収で確認すること

ホスト報酬が所得税法上のどの支払類型に当たるかは、契約と実態、居住地、サービス内容で確認する必要がある。国税庁は、源泉徴収対象の報酬・料金を列挙しており、「ホステス等に支払う報酬・料金」も別途対象としている。したがって、呼称を「ホスト」「クリエイター」に変えるだけで判断を回避できるものではない。

根拠:

- [国税庁 No.2792 源泉徴収が必要な報酬・料金等](https://www.nta.go.jp/taxes/shiraberu/taxanswer/gensen/2792.htm)
- [国税庁 No.2793 報酬・料金等の源泉徴収義務者](https://www.nta.go.jp/taxes/shiraberu/taxanswer/gensen/2793.htm)

開始前に税理士等へ確認する質問:

1. 日本居住ホストへの通話・ギフト連動報酬は、給与か、どの報酬・料金に当たるか。
2. 源泉徴収、支払調書、消費税・インボイスの扱いはどうなるか。
3. 海外居住ホストへの支払いに、日本側の源泉徴収や租税条約の確認が要るか。
4. 運営が個人の間、法人化後で、記帳・消費税・海外送金の事務はどう変わるか。

## 5. 個人情報・通報証拠画像

顔画像、本人確認情報、通話時の証拠画像、IP 等は、取扱いによって個人情報になり得る。特に通報時の画像は目的外利用をせず、最小限の保存にする。

初期方針:

- 通報時だけ静止画を1枚取得し、目的を「安全調査・利用停止判断・異議対応」に限定する。
- 保存は30日で自動削除し、延長は異議・重大調査に必要な場合だけ記録を残して行う。
- 管理画面は最小権限、強い認証、操作ログ、暗号化された保存先、ダウンロード制限を用意する。
- プライバシーポリシーに、取得項目、目的、保存期間、委託先、削除・問い合わせ窓口を明示する。
- 漏えい時の検知、隔離、本人通知、当局報告の手順を事前に用意する。

根拠:

- [個人情報保護委員会・通則ガイドライン](https://www.ppc.go.jp/personalinfo/legal/guidelines_tsusoku/) — 安全管理措置、委託先監督、漏えい時の報告・通知を扱う。
- [個人情報保護委員会・漏えい等対応](https://www.ppc.go.jp/personalinfo/legal/leakAction/) — 一定の漏えいで速報は概ね3〜5日、確報は原則30日（不正目的のおそれは60日）の案内。

## 6. 年齢確認・本人確認・海外利用者／ホスト

有料ホスト版は、利用者・ホストとも成人限定にする。自己申告だけでなく、少なくともホストは Stripe Connect 等の本人確認と、プラットフォーム側の年齢・国・禁止行為チェックを分けて実施する。利用者も、コイン購入前に成人確認・利用規約同意・禁止行為の再確認を行う。

海外の利用者・ホストを扱う場合:

- Connect の対応国、本人確認要件、各国への払出し可否を、対象国ごとに Stripe の最新資料で確認する。
- 居住国の消費者保護、税、年齢、コンテンツ規制は一律ではないため、最初は対象国を限定する。
- 海外のクラウド・決済事業者へ個人データを提供する場合、日本の個人情報保護法上の外国第三者提供・委託の整理と、利用者への情報提供／同意設計を確認する。

根拠:

- [Stripe Connect の仕組みと提供国](https://docs.stripe.com/connect/how-connect-works)
- [個人情報保護委員会・外国にある第三者への提供](https://www.ppc.go.jp/personalinfo/legal/guidelines_offshore/)

## 7. 決済会社の禁止業種・審査

Stripe の公開ポリシーは、性的満足を目的とするコンテンツ、性的サービス、成人ライブチャット機能等を禁止・制限対象に含めている。したがって、画面や広告が「女性と話せる」「ギフトで親密になれる」等、性的・出会い系サービスに見えると、非性的な意図でも審査・継続利用のリスクが高い。

根拠:

- [Stripe の禁止・制限業種 FAQ](https://support.stripe.com/questions/prohibited-and-restricted-businesses-list-faqs)
- [Stripe の禁止・制限業種リスト](https://stripe.com/en-br/legal/restricted-businesses) — 日本向け項目に「特定商取引法上の表示ページがない事業」も掲載。

審査前に提示する資料:

- 非性的な文化交流・言語会話だけを目的とする明確なサービス説明
- 性的内容・ヌード・恋愛目的・勧誘の禁止規約、通報、停止、モデレーション体制
- 年齢・本人確認のフロー、ホスト契約、返金・不正利用ポリシー
- 事業者情報、問い合わせ窓口、必要な特定商取引法上の表示
- 決済画面、コイン価格、通話課金・ギフトの表示、返金条件の実画面案

**「成人女性とのライブチャット」を売り文句にしたり、性的な集客・広告素材を使ったりしないこと。** その時点で本計画の非性的前提から外れ、Stripe 利用不可となるリスクが非常に高い。

- [ ] 対象国を絞り、Connect のオンボード・払出し可否を確認した
- [ ] 成人確認・ホスト本人確認・制裁対象チェックのフローを設計した
- [ ] 非性的方針、禁止行為、通報、返金、異議申立てを規約と画面へ反映した
- [ ] 決済・通話・報酬・返金・払出しを照合できる台帳を実装した
- [ ] チャージバックと負の残高の負担者、保留・払出しルールを決めた
- [ ] ホスト契約を雇用／業務委託の実態に合わせて作成した
- [ ] 税理士に源泉徴収、支払調書、消費税、海外ホスト支払を確認した

- [ ] プライバシーポリシー、特定商取引法上の表示、問い合わせ窓口を公開した
- [ ] 利用者が少ない限定ベータで、通話品質・不正・返金・モデレーション負荷を検証した

## この時点での未確定点

1. Stripe が RandomCam の具体的な画面・宣伝文・収益設計を承認するか。
2. 日本居住／海外居住ホストごとの契約類型、源泉・税務・保険の扱い。
3. 対象国ごとの年齢、消費者保護、税、データ移転の要件。
4. コインの法的・会計上の扱い、失効・返金・残高の管理方法。

この文書は公開一次資料から作成した事業検討メモであり、個別事案に対する法律・税務判断ではない。実装・課金開始の直前に、対象国と確定した画面・契約・資金フローを提示して弁護士、税理士、決済会社へ確認する。
